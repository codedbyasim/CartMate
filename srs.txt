1. Introduction
1.1 Purpose
This Software Requirements Specification (SRS) document defines the functional and non-functional requirements for EchoShop — an AI-powered conversational commerce agent. The system enables users to discover products and find visually similar items through natural spoken language and live camera input, eliminating the dependency on text-based keyword search.
This document is intended for the following audiences: developers implementing the system, judges evaluating the hackathon submission, and stakeholders assessing the commercial viability of the platform.

1.2 Scope
EchoShop is a web-based AI agent that integrates two primary AI capabilities:
•	Voice-Powered Product Discovery: The user speaks naturally to describe product intent, and the system interprets context, asks clarifying questions, and returns ranked product recommendations.
•	Visual Product Matching: The user presents a physical object or image to a camera, and the system identifies visually similar products from a catalogue.
The system is designed for deployment in e-commerce platforms targeting users who struggle with conventional text-based search — including non-technical users, elderly users, and users in low-literacy contexts. It is out of scope for this version to handle payment processing, order fulfilment, or return resolution workflows.

2. Overall Description
2.1 Product Perspective
EchoShop is a standalone, browser-based web application that functions as an autonomous conversational shopping agent. It does not replace an existing e-commerce platform; rather, it acts as an intelligent front-end layer that sits on top of any product catalogue exposed via API or database query.
The system is composed of three loosely coupled subsystems:
•	Voice Interface Subsystem — Captures and streams microphone audio to the Speechmatics STT API and converts agent responses back to audio via the browser Web Speech API.
•	AI Reasoning Subsystem — Processes transcribed text through Gemini Pro to generate intent-aware, multi-turn conversational responses and product recommendations.
•	Visual Matching Subsystem — Captures webcam frames and submits them to Gemini Vision to identify visual attributes and retrieve matching products.

2.2 Product Functions — High-Level Summary
The following table summarises the primary capabilities of EchoShop:

Capability	Summary
Voice-Powered Product Discovery	User speaks a natural-language product description; agent asks follow-up questions and recommends ranked products
Contextual Conversation Memory	Agent retains the full dialogue history within a session to resolve pronouns and preferences without repetition
Visual Product Matching	User shows a physical item or image to the webcam; agent identifies visual similarity and finds matching catalogue items
Multi-turn Dialogue Management	Agent autonomously decides when sufficient information has been gathered before generating recommendations
Accessibility-First Voice UX	All interactions are available via voice input and audio output; no typing is required at any step

2.3 User Classes and Characteristics
2.3.1 Primary User — Conversational Shopper
This user prefers to describe what they need in spoken language rather than typing keywords. They may be unfamiliar with e-commerce category taxonomy. They expect the system to understand vague or emotionally driven requests (e.g., 'something nice for my mother's birthday') without requiring structured input.
2.3.2 Accessibility User — Non-Technical / Low-Literacy
This user cannot efficiently use text-based search. They may have limited reading ability, motor impairments preventing typing, or may be elderly. This user class is the primary motivation for the voice-first design. All core functionality must be operable without typing.
2.3.3 Visual Searcher
This user has a physical item, printed image, or on-screen image that represents what they want to buy. They want to find the same or similar product online without describing it verbally or textually. This user interacts primarily with the camera feature.
2.3.4 Platform Administrator
A technical user responsible for connecting the product catalogue, configuring API credentials, and monitoring system health. This user interacts with the backend configuration and is not exposed to the conversational UI.

2.4 Operating Environment
•	Client: Modern web browser (Chrome 110+, Firefox 115+, Edge 110+) with WebSocket support, microphone access, and camera access.
•	Server: Python FastAPI application deployed on a Vultr Virtual Machine running Ubuntu 22.04 LTS.
•	External APIs: Speechmatics Real-Time API (WebSocket), Google Gemini Pro API, Google Gemini Vision API, Browser Web Speech API (TTS).
•	Network: Minimum 2 Mbps upload bandwidth for real-time audio streaming; minimum 5 Mbps for simultaneous audio and video.

2.5 Design and Implementation Constraints
•	The system must not store raw audio recordings on the server. All audio is streamed directly to the Speechmatics API and discarded after transcription.
•	All LLM prompts and conversation histories must remain within a single session and must not persist to a database without explicit user consent.
•	The frontend must be a single-page application (SPA) to avoid page reload interruptions during active voice sessions.
•	The Gemini API must be called from the server side only; API keys must never be exposed to the browser client.
•	The system must comply with GDPR principles: no personally identifiable voice data is retained beyond the active session.
•	TTS must use the browser-native Web Speech API to avoid adding an additional paid service dependency during the hackathon phase.

2.6 Assumptions and Dependencies
•	The product catalogue is available as a queryable JSON data source or mock REST API. Integration with a live e-commerce backend (Shopify, WooCommerce) is outside MVP scope.
•	Speechmatics API credits are available as provided by the hackathon partner ($200 per participant).
•	Google Gemini API free tier or Google Cloud credits ($300) are sufficient for the demonstration workload.
•	Users grant microphone and camera permissions in the browser when prompted.
•	The system assumes English as the primary language for MVP. Multilingual support is a post-hackathon enhancement.
•	Internet connectivity is available and stable at the demonstration venue.

5. External Interface Requirements
5.1 User Interface
The EchoShop UI is a single-page web application with the following distinct regions:
•	Header Bar: Displays the application name, session status indicator, and the mute toggle for TTS.
•	Conversation Panel: A vertically scrolling panel that displays the full dialogue history as styled message bubbles, distinguishing user input (right-aligned) from agent responses (left-aligned). Product recommendation cards are rendered inline within agent response bubbles.
•	Product Card: Displays product thumbnail, name, price, and a one-sentence justification. Each card includes a 'View' action button.
•	Voice Control Bar: Fixed at the bottom of the screen. Contains the microphone button (push-to-speak or toggle), a real-time transcription preview area, and a camera capture button.
•	Camera Preview Panel: Appears as an overlay when camera mode is activated, showing the live video feed and a capture button.
•	Status Indicators: Animated icons show microphone active, camera active, and API processing states.

5.2 Speechmatics Real-Time API Interface
Protocol	WebSocket (WSS)
Endpoint	wss://eu2.rt.speechmatics.com/v2
Authentication	Bearer token passed in the StartRecognition message payload
Audio Format	Raw PCM, 16 kHz sample rate, 16-bit depth, mono channel
Input	Continuous audio chunks streamed from browser MediaRecorder
Output	JSON messages of types: RecognitionStarted, AddPartialTranscript, AddTranscript, EndOfTranscript
Relevant Fields	transcript (string), is_eos (boolean), duration (float)
Error Handling	On WebSocket close code 4xxx, display user-facing error and offer retry

5.3 Google Gemini Pro API Interface
Protocol	HTTPS REST
Endpoint	https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent
Authentication	API key passed as query parameter or Authorization header from server only
Input	JSON body containing: system instruction (string), conversation history (array of role/content pairs), user message (string)
Output	JSON response with candidates[0].content.parts[0].text (string)
Max Tokens	1,024 output tokens per request for agent responses
Temperature	0.4 (balanced between creativity and factual consistency)
Error Handling	On HTTP 429 (rate limit), implement exponential backoff with a maximum of 3 retries; on HTTP 500+, display user-facing error

5.4 Google Gemini Vision API Interface
Protocol	HTTPS REST
Endpoint	https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent
Authentication	API key passed as Authorization header from server only
Input	JSON body with multipart content: inline_data (Base64 JPEG, mime_type: image/jpeg) and a structured analysis prompt
Image Size Limit	Maximum 5 MB per image; images exceeding this limit shall be rejected client-side before transmission
Output	JSON response containing structured visual attribute extraction in text form
Error Handling	On HTTP 400 (invalid image), display user-facing error instructing user to retake the photo in better lighting; on timeout (>15s), display error and re-enable camera

5.5 Browser Web Speech API (TTS) Interface
Interface	window.speechSynthesis (SpeechSynthesis)
Method	speechSynthesis.speak(utterance: SpeechSynthesisUtterance)
Voice	Preferred: en-US or en-GB voice; fallback to browser default if unavailable
Rate	1.0 (normal speed)
Pitch	1.0 (normal pitch)
Cancel Method	speechSynthesis.cancel() — called before each new utterance to prevent overlap
Constraints	Behaviour varies across browsers; Chrome requires a user gesture before first TTS call. System handles this by triggering a silent utterance on first microphone activation.

6. System Architecture
6.1 Architectural Overview
EchoShop follows a client-server architecture with a thin browser client responsible for media capture and UI rendering, and a Python FastAPI server responsible for all AI API interactions, session state management, and product catalogue queries. This separation ensures that no API credentials are exposed on the client side.

6.2 Component Descriptions
6.2.1 Browser Client (Frontend)
•	Technology: React.js (single-page application)
•	Responsibilities: Microphone capture via MediaRecorder API, WebSocket audio streaming to server, live transcription display, camera capture via getUserMedia API, image encoding and upload, conversation history rendering, TTS playback via Web Speech API, UI state management.
•	Communication: WebSocket (WSS) for audio streaming; HTTPS REST for image upload and session management.
6.2.2 Application Server (Backend)
•	Technology: Python 3.11, FastAPI framework
•	Responsibilities: WebSocket proxy relay to Speechmatics API, Gemini Pro API calls with conversation history, Gemini Vision API calls for image analysis, product catalogue search and ranking, session state storage in server memory, API key management.
•	Deployment: Vultr Virtual Machine (Ubuntu 22.04 LTS), accessible via public IP with HTTPS via reverse proxy (Nginx + Let's Encrypt).
6.2.3 Speechmatics STT Service (External)
•	Role: Converts streaming audio to text in real time.
•	Integration Point: Server opens a WSS connection to Speechmatics on behalf of the client, forwarding audio chunks received from the client WebSocket.
6.2.4 Google Gemini Pro (External)
•	Role: Conversational reasoning, intent extraction, clarifying question generation, and product recommendation narrative generation.
•	Integration Point: Server calls the Gemini REST API synchronously on each user turn, passing full session history.
6.2.5 Google Gemini Vision (External)
•	Role: Visual attribute extraction from user-submitted images.
•	Integration Point: Server calls the Gemini multimodal REST API with a Base64-encoded image and a structured extraction prompt.
6.2.6 Product Catalogue (Internal)
•	Role: Structured data store of available products.
•	Implementation: JSON file loaded into server memory at startup; queried via an in-process search function using keyword matching and tag filtering.

6.3 Data Flow — Voice Product Discovery
The following sequence describes the complete data flow for a voice-initiated product search:
1.	User presses the microphone button. Browser requests microphone permission if not already granted.
2.	Browser captures audio via MediaRecorder and opens a WebSocket connection to the application server.
3.	Server relays audio chunks over a new WSS connection to the Speechmatics Real-Time API.
4.	Speechmatics returns partial transcript events; server forwards these to the browser for real-time display.
5.	On end-of-utterance, Speechmatics returns a final transcript; the WebSocket connection to Speechmatics is closed.
6.	Server appends the final transcript to the session conversation history and constructs a Gemini Pro API request containing the system prompt and full history.
7.	Gemini Pro returns an agent response (clarifying question or product recommendations).
8.	Server appends the agent response to the session history and returns the response text to the browser via WebSocket.
9.	Browser renders the response as a conversation bubble and triggers TTS playback via the Web Speech API.

6.4 Data Flow — Visual Product Matching
The following sequence describes the complete data flow for a camera-initiated visual search:
10.	User activates camera mode. Browser requests camera permission if not already granted.
11.	Browser displays live video preview. User presses capture button.
12.	Browser encodes the captured frame as Base64 JPEG and POSTs it to the server's image analysis endpoint over HTTPS.
13.	Server constructs a Gemini Vision API request with the Base64 image and a structured prompt requesting visual attribute extraction.
14.	Gemini Vision returns a text response listing identified attributes (category, colour, material, style, brand if visible).
15.	Server parses the extracted attributes and executes a filtered query against the product catalogue.
16.	Server constructs a ranked list of matching products and returns it to the browser as a JSON response.
17.	Browser renders the product cards in the conversation panel and triggers TTS reading of the summary.
18.	Server discards the image data from memory. No image is written to disk.

•	Personalisation based on purchase history or user profile data.
•	A/B testing infrastructure for recommendation quality.
